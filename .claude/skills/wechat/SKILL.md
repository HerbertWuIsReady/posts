# 微信公众号成稿

输入是一份素材（调研笔记、官方文档摘录、草稿）。输出是一篇可以直接发的公众号文章 ——
**写作手法和视觉格式都要复刻参考风格**，不是只套个样式。

## 你做什么，不做什么

| 你做 | 脚本 `to_html.py` 做 |
|---|---|
| 按下面的写作手法重构内容 | 套字号、颜色、行高、间距 |
| 判断章节怎么切、每章配什么卡片 | 渲染章节标题块的五层结构 |
| 判断哪句进引用框、哪些是关键概念 | 画徽章、斑马纹、卡片 |

**绝不手写内联样式。** 数值全在 `theme.yaml`，你写了只会和全文不一致。

## 输入输出

```
读   content/<slug>/source.md        素材
写   content/<slug>/post.wechat.md   成稿 + 排版标注
跑   python .claude/skills/wechat/to_html.py content/<slug>
得   content/<slug>/out/wechat.html  贴进编辑器的成品
```

# 一、写作手法

## 1. 全文骨架

```
PART 01  公司速览 / 背景          ← 先给读者坐标系
PART 02  一、<第一条主线>          ← 每个 PART 一章，章内用 ## 分小节
PART 03  二、<第二条主线>
...
PART 0N  N、横向对比 / 结论        ← 用表格收尾
```

每章开头配一张 `fig` 卡片。卡片编号连续：`01/07`、`02/07` …… 分母是全文卡片总数。

## 2. 阅读节奏

```
提出问题 → 解释背景 → 拆解逻辑 → 案例与证据 → 提炼结论
```

每章内部也走这条线，不只是全文。

## 3. 事实密度 —— 这是这个风格的命门

- **每个事实带日期**：「Horizon Catalog 是 2025-11-04 在 BUILD 大会上 GA 的」，不写「最近发布」
- **每个数字带口径和同比**：「全球客户 13,328 家（同比 +21%），其中 Forbes Global 2000 占 790 家（同比 +5%）」
- **官方定位用英文原文**，放 `> [!quote]` 斜体框，不要自己翻译后当事实引用
- **区分事实层级**：官方公告 / 官方文档 / 第三方报道 / 你的推断。推断必须写明「这是推断，没有对称的公开文档」
- 素材里没有的数字**不要补**。宁可写「官方未披露」

## 4. 对比用表格

横向对比一定走表格，不走段落。列头是对象，行头是维度，维度名用 `==维度==` 标成强调色。
表格之后紧跟一段收束：「N 个维度对比下来，三个最显著的差异点是……」

## 5. 语言

- 中英文之间加空格：`微信 API`，不是 `微信API`
- 产品名、API 名保持原文大小写：`Horizon Catalog`、`KG_EDGE`、`recursive CTE`
- 不用「赋能」「抓手」「闭环」
- 每段一个完整观点，不超过 3 行（手机屏幕）

# 二、标注语法

## 章节标题块

```markdown
# 一、Snowflake 的本体论起源，从 Cortex 到 Horizon {SNOWFLAKE}
```

`{}` 里是英文副标（可省）。PART 编号自动按出现顺序生成。
脚本会渲染成五层：满宽深蓝粗线 → `PART 02` → 主标题 → `—SNOWFLAKE` → 短下划线，全部居中。

## 信息图卡片

```markdown
:::fig 01/07
eyebrow:    COVER · 厂商产品解剖系列 第 4 篇
title:      Snowflake 4 大产品
title:      从企业级湖仓
title-red:  到 AI 智能体
sub:        Horizon Catalog GA · Semantic Studio preview · Knowledge Graph
line:       4 个产品 · 2 个发布日 · 1 个主线：把 ontology 塞进 warehouse
stat:       4/2/1
stat-label: 产品 / 发布日 / 主线
source:     Snowflake 官方公告 + 官方 Docs + 第三方权威报道
layers:     三层事实分层 62% / 25% / 13% · 25 数据来源 · 2026-09-19
watermark:  公众号 · 你的号名
:::
```

- `title` 可重复，每行一行大字；`title-red` 是其中标红的那行（通常是结论性的一行）
- `stat` 是右下角大号红字，必须是从本章内容里提炼的数字，不能编
- `layers:` 事实来源分层说明，`watermark:` 右下角公众号署名，`caption:` 卡片下方居中图说 —— 均可省
- 卡片编号 `FIG 01/07` 自动渲染在右下角

卡片是 HTML 渲染的，**不需要上传素材库**。

## 其余

| 标注 | 用途 |
|---|---|
| `## ` | 小节标题 |
| `**text**` | 核心结论，加粗 |
| `==text==` | 关键概念 / 列表引导词 / 表格维度名，强调色 |
| `> [!insight]` | 你提炼的核心洞察 |
| `> [!quote]` | 官方原文引用，自动斜体 |
| `1. ==Collect==: 内容` | 编号列表，渲染成蓝色实心圆徽章 |
| `- ` | 无序列表 |
| `---` | 大话题转场 |
| `![图说](assets/x.png)` | 真实图片，需手动上传素材库 |
| 表格、代码块 | 标准 Markdown |

# 三、平台限制

| 情况 | 怎么办 |
|---|---|
| **外链** | 微信正文禁外链。正文保留文字，脚本自动把 URL 收进文末「参考」 |
| **真实图片** | 必须上传素材库。脚本渲染成灰框占位，发布时手动替换 |
| **代码块** | 微信不支持语法高亮，单色处理，不要尝试着色 |
| **LaTeX** | 简单的转 Unicode（`x²`、`α`）。复杂公式写进 `fig` 卡片，或标 `<!-- 需转图片 -->` |
| **表格** | 最多 3 列。更多列在手机上必然横向溢出，改成分层列表或拆成两张表 |

# 四、内容保真红线

1. 不改变素材里的事实、观点、结论
2. 不为排版删减专业内容
3. 不把论证性段落强行改成列表
4. 保留原文的逻辑递进
5. 技术名词、英文缩写、公式保持准确
6. 可以拆长段、重排章节顺序，**不得新增素材里没有的事实或数字**

# 五、流程

1. **通读素材**，先定全文骨架：分几章、每章主线是什么、卡片放几张
2. 读 `../../../reference/style-guide.md`
3. 写 `post.wechat.md`
4. 跑 `to_html.py`
5. 照 `checklist.md` 核对
6. **在对话里**报告：分了几章、几张卡片、几个引用框、哪些地方素材不足没敢补、哪些图要手动上传

第 6 步不写进正文。正文里不解释排版过程。
